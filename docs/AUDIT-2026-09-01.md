# EXP-001 pre-result implementation audit — 2026-09-01

**Scope:** `state-promotion` EXP-001 scaffold, before inspecting any language-model result.

## Gate decision

EXP-001 language-model results were **not yet admissible** from the recovered scaffold. Two implementation details could bias B5 relative to the baselines. Both were corrected before any EXP-001 LM score was inspected.

## Critical finding 1 — held-out evaluation leakage into B5 routing

The recovered runner supplied held-out `test` examples to `guarded_promotion` as its current and protected evidence. Although the examples were not differentiated through, their labels influenced commit/rollback decisions. This is evaluation leakage: B5 could adapt its update policy using information unavailable to B0–B4.

### Correction

- Current promotion evidence is now formed only from already-observed current-segment **training** examples.
- Retention evidence is now formed only from the bounded replay reservoir.
- On revision streams, replay items made obsolete by an observed superseding target are excluded from the protected probe.
- `guarded_promotion` fails closed if any non-training example reaches the gate.
- Each promotion manifest records probe counts, SHA-256 hashes, and `heldout_gate_example_count`; the validator requires the leak count to be zero.
- Gate forward passes are counted separately as decision-time inference compute.

Recorded as **EXP-001 preregistration Amendment B**.

## Critical finding 2 — nominally continuous baselines lost Adam state at every segment

The recovered B1/B2 runner recreated AdamW at synthetic stream boundaries. The adapter weights persisted, but optimizer moments did not. This weakens the baseline for an orchestration reason that is not part of the condition definition.

### Correction

- B1/B2 now retain AdamW state across segment boundaries.
- Two-timescale arms retain the fast optimizer while the fast state persists.
- Resetting fast parameters after accepted consolidation also resets their optimizer state.
- Declined/rolled-back promotion keeps the active fast optimizer because the fast parameter state remains active.
- Prompt-state initialization is explicitly paired by lifetime seed across methods.

Recorded as **EXP-001 preregistration Amendment C**.

## Critical finding 3 — B3/B4 and B5 were not architecture matched on latent state

The recovered fixed/random controls did not use persistent latent state while B5 did. A B5-vs-B3/B4 difference would therefore mix routing-policy effects with access to an extra persistent state channel.

### Correction

- Fixed, random, and learned-promotion two-timescale arms now use the same latent-state mechanism.
- The `promotion-no-latent` condition remains the explicit latent-state ablation.
- Manifests record `latent_state_enabled`, and validation rejects a routing-control architecture mismatch.

Recorded as **EXP-001 preregistration Amendment D**.

## Workflow correction

The recovered `make lm-pilot` command ran only B5. It now invokes the full EXP-001 pilot harness, including primary baselines, the post-hoc commit-matched random-routing control, and manifest validation. A separate `make lm-pilot-revision` target covers the revision stream.

## Remaining pre-confirmatory blockers

These are deliberately **not** paper-result blockers for an engineering pilot, but they prevent protocol v1.0 from being frozen today:

1. Use development-only seeds to verify that PALS is non-ceiling and exhibits enough interference to measure forgetting.
2. Freeze a strong fixed-routing cadence and B5 gate thresholds using development seeds only; confirmatory seeds must remain untouched.
3. Freeze immutable model/tokenizer revisions rather than only a repository name.
4. Produce an exact dependency/environment lock on the machine that will run the experiment.
5. Run from a real code commit. The harness now records a deterministic `source_tree_sha256` so archive-based pilots still have provenance, but that hash is not a substitute for the confirmatory commit required by the protocol.

## Next admissible action

Run the engineering pilot only after the local environment satisfies the model/dependency preflight. Treat all outputs as **PILOT**, inspect the validator result and resource manifests first, and do not promote them into H1 evidence. Freeze protocol v1.0 and a code commit only after the pilot exposes no further ceiling, leakage, budget, or baseline-fidelity blocker.
